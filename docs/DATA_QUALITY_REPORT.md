# defense-research-agent 데이터 품질 보고서

## 1. 평가 기준

평가 대상은 다음 세 층으로 구분했다.

- 실제 파일: PDF 371개, JSON 373개, `.DS_Store` 3개
- 문서 메타데이터: 문서별 JSON 372개
- 중복 대상을 합친 기준 집합: 고유 PDF-메타데이터 연결 370개

텍스트 길이, 빈 페이지, 유형별 통계는 중복 JSON이 수치를 부풀리지 않도록 고유 연결 370개를 기준으로 계산했다. 파일 개수와 파일명 문제는 실제 디렉터리의 모든 파일을 기준으로 계산했다.

심각도 정의:

- **높음**: 검색·평가 결과를 잘못 만들거나 문서를 누락/중복시킬 수 있어 파일럿 색인 전에 차단해야 함
- **중간**: 결과의 설명 가능성·정규화·이식성을 해치므로 파일럿에서 명시적 보정 또는 경고가 필요함
- **낮음**: 즉시 결과를 깨뜨리지는 않지만 장기 운영 전에 정리해야 함

## 3. 누락값과 콘텐츠 완전성

### 3.1 구조적 누락

문서 JSON 372개는 공통 스키마의 필드를 빠짐없이 가진다. `full_text`도 빈 문자열인 레코드는 없다. 그러나 연구에 필요한 다음 필드는 스키마 자체에 없다.

- 제목
- 저자 및 공저자 배열
- 발행일/발행연월
- 권·호·통권·쪽수
- 초록/요약
- DOI
- 키워드
- 원문 URL
- 언어

이는 JSON 파싱 관점의 누락값은 아니지만 검색·중복 제거·근거 제시 관점에서는 핵심 메타데이터 누락이다.

### 3.2 본문 추출 누락

고유 연결 370개 중:

- 38개가 `full_text` 1,000자 이하
  - `Brief`: 37개
  - `연구보고서`: 1개
- 33개가 100자 이하
- 70개 문서에 적어도 한 쪽의 추출 텍스트가 비어 있음
- 전체 메타데이터 페이지 7,158쪽 중 236쪽이 빈 텍스트
  - `Brief`: 99쪽
  - `국방정책연구`: 4쪽
  - `연구보고서`: 133쪽
  - `국방논단`: 0쪽

대표 저추출 PDF를 렌더링했을 때 실제 본문이 보였다. 따라서 이 38개를 “본문이 없는 공개본”으로 일괄 판단하면 안 된다. 기본 상태는 `extraction_failed_or_incomplete`가 적절하다.

### 3.3 초록과 본문 유무

- 모든 고유 레코드의 `full_text`는 비어 있지 않지만, 위 38개는 본문으로 사용하기에 불충분하다.
- `국방정책연구` 고유 59개 모두 추출 텍스트에 영문 `Abstract`와 `Keywords` 신호가 있다.
- `Brief`는 주로 `배경과 목적`, `수행 결과` 구조이며 별도 초록 필드는 없다.
- `국방논단`은 표지의 요약 성격 문단과 본문이 있으나 별도 초록 필드는 없다.
- `연구보고서`는 전체 보고서와 몇 쪽짜리 공개 요약본이 섞여 있으며, 초록·요약 표기가 일관되지 않다.

초록 존재 여부는 `abstract is null` 같은 단일 규칙이 아니라 `abstract_text`, `summary_text`, `content_scope`와 추출 신뢰도로 분리해야 한다.

## 4. 중복

### 4.1 바이트 동일 중복

- SHA-256 기준 동일 PDF 그룹: 0
- SHA-256 기준 동일 JSON 그룹: 0

### 4.2 논리 중복

다음 `국방정책연구` PDF 하나를 문서 JSON 3개가 가리킨다.

```text
2025_김민관_북한의대남심리전변화분석2016년대남전단과2024년오물풍선비교를ᄌ.pdf
```

연결된 JSON 파일명은 같은 stem의 기본 파일, ` 2.json`, ` 3.json`이다. 세 레코드는 `full_text`와 `page_texts`가 동일하고 `processed_date`만 서로 다르다. 세 JSON의 바이트 해시가 다른 이유다.

권고:

- 문서 ID는 JSON 파일 경로나 처리 시각이 아니라 PDF 콘텐츠 해시와 정규화된 자료 유형을 기반으로 생성한다.
- 동일 PDF에 여러 레코드가 연결되면 가장 최신 레코드를 자동 선택하지 말고 동일성 검사 결과와 선택 규칙을 감사 로그에 남긴다.
- 원본 JSON은 삭제하지 않는다.

## 5. 문자 인코딩과 추출 문자

### 5.1 파일 인코딩

- JSON 373개는 모두 UTF-8 디코딩과 JSON 파싱에 성공했다.
- 대체문자 `U+FFFD`가 들어간 문서 텍스트는 없었다.
- 한글 파일명은 NFC와 분해형이 혼재한다.

따라서 파일 자체의 문자셋은 UTF-8로 고정할 수 있지만, 파일명 비교 전에는 NFC 정규화가 필요하다.

### 5.2 제어문자

고유 문서 370개 중 192개에 줄바꿈·탭을 제외한 C0/C1 제어문자가 있다.

- `국방논단`: 100/100
- `국방정책연구`: 59/59
- `Brief`: 28/173
- `연구보고서`: 5/38

다수 문서는 `U+0001`을 시각적 공백이나 열 구분처럼 사용한다. 다음 연구보고서는 더 심각하다.

```text
data/metadata/2023_이상국_인태지역주요군사력과전략동향.json
```

- 제어문자: 253,227개
- `full_text` 대비 비율: 약 39.9%
- NUL과 C0/C1 범위의 다양한 값이 함께 존재
- PDF 첫 페이지는 렌더링 시 정상

이는 UTF-8 디코딩 실패가 아니라 PDF 글꼴/ToUnicode 매핑 또는 추출기 문제다. 검색 인덱스에 그대로 넣으면 토큰화와 유사도 계산을 심각하게 오염시킬 수 있다.

권고:

- 원본 `full_text`는 보존한다.
- 색인용 파생 텍스트에서 허용 문자 정책을 적용한다.
- 제어문자 비율, 한글/인쇄 가능 문자 비율, 쪽당 문자 수로 품질 점수를 계산한다.
- 임계값 초과 문서는 OCR 또는 대체 추출기 대기열로 보내고 자동 색인하지 않는다.

## 6. 날짜 형식과 의미

관찰된 날짜 관련 값은 서로 다른 의미를 가진다.

| 위치 | 예 | 의미/문제 |
|---|---|---|
| 파일명 선두 | `2024_...pdf` | 파일 분류 연도. 정확한 발행일과 다를 수 있음 |
| `metadata.processed_date` | `2026-02-02T23:30:06.937817` | 추출 처리 시각. 발행일이 아님 |
| 국방논단 본문 | `2024년 11월 4일` | 일 단위 발행일 |
| 국방정책연구 본문 | `2024년 여름(40-2)` | 계절호·권호 기반 발행 표기 |
| 연구보고서 본문 | `2024. 2.` | 월 단위 발행일 |
| Brief 본문/제목 | `2019 ...`, `2020. 7.` | 사업연도·발행연월이 함께 나타날 수 있음 |

문서 JSON 372개의 `processed_date`는 모두 마이크로초가 포함된 ISO 형식이며 범위는 2026-01-31~2026-02-02다.

권고 파생 필드:

- `filename_year`: 파일명에서 그대로 추출
- `published_at`: 확인 가능한 정규화 발행일
- `published_precision`: `day`, `month`, `season`, `year`, `unknown`
- `issue_label`: 원문의 계절·권호·호수
- `processed_at`: 기존 `processed_date`
- `date_evidence`: 값의 근거 페이지와 원문

파일명 연도와 본문 발행 연도가 다르면 자동 덮어쓰지 말고 경고와 함께 둘 다 보존해야 한다.

## 7. 저자 표기

- PDF 371개 파일명의 대표저자 구간은 모두 구문상 식별 가능하다.
- 파일명은 대체로 대표저자 한 명만 제공한다.
- 실제 표지에는 복수 저자, 직급, 센터, 소속, 이메일이 함께 나타난다.
- `국방정책연구`는 저자명 뒤 `*`, `**`와 각주로 소속을 연결한다.
- 고유 메타데이터 370개 중 연구보고서 3개는 파일명의 대표저자 문자열이 `full_text`에 나타나지 않았다. 1개는 심각한 저추출 문서이고, 나머지도 텍스트/표기 파싱 검토가 필요하다.

권고 스키마:

```text
authors[]:
  name
  role
  affiliation
  email
  is_primary
  raw_text
  evidence_page
  confidence
```

저자명은 파일명에서만 확정하지 말고 표지를 우선하며, 파일명 값은 별도 `filename_author`로 보존한다.

## 8. HTML과 마크다운 포함 여부

의도적으로 저장된 HTML 또는 마크다운 문서는 확인되지 않았다.

- HTML 문서 구조 태그는 없다.
- 마크다운 코드 펜스는 0개다.
- 일부 `#`, `**`, `[텍스트](텍스트)` 형태가 보이지만 저자 각주, 통계 표기, 원문 주석 또는 손상된 추출 문자열이다.
- 심각하게 손상된 연구보고서에서 임의 바이트열이 HTML 태그처럼 보이는 오탐이 발생한다.

따라서 `full_text`를 HTML/Markdown으로 렌더링하면 안 된다. 기본적으로 신뢰되지 않은 평문으로 취급하고 UI에서는 이스케이프해야 한다.

## 9. PDF와 메타데이터 연결 품질

### 9.1 확인된 연결

- 문서 JSON 372개는 NFC 정규화한 `(category, filename)`으로 모두 PDF에 연결됐다.
- 논리 중복을 제거하면 고유 연결은 370개다.
- 연결된 모든 레코드의 `num_pages`는 실제 PDF 페이지 수와 일치했다.
- 연결된 모든 레코드의 `file_size_mb`는 현재 PDF 크기를 MiB로 소수 둘째 자리 반올림한 값과 일치했다.

### 9.2 누락된 메타데이터

다음 12쪽 `국방논단` PDF에는 문서 JSON이 없다.

```text
2024_탁성한_〔제2000호특집〕기후변화를고려한국방혁신4.0발전제언.pdf
```

### 9.3 연결에 쓰면 안 되는 값

- `metadata.path`: 372개 모두 저장소 밖의 과거 절대 경로
- JSON 파일명: 50/372개가 대상 PDF stem과 다름
- 파일명 원시 바이트: NFC/NFD 혼재로 운영체제 간 불일치 가능

권고 연결 키:

1. 현재 스캔한 PDF의 SHA-256
2. NFC 정규화 `category`
3. NFC 정규화 `metadata.filename`
4. 충돌 시 실제 PDF 크기와 페이지 수

원본 경로와 원본 파일명은 표시·감사를 위해 별도로 보존한다.

## 11. 문자 수와 집계 필드

- 고유 레코드 370개 모두에서 `page_texts[].char_count == len(page_texts[].text)`가 성립한다.
- 모든 페이지 번호가 1부터 시작해 연속적이다.
- `metadata.num_pages == len(page_texts)`가 모든 레코드에서 성립한다.
- `metadata.avg_chars_per_page == round(total_chars / num_pages)`가 모든 레코드에서 성립한다.
- 그러나 `metadata.total_chars != len(full_text)`이며 차이는 항상 +2~+12다.

이는 페이지 결합 시 구분자 계산 방식 차이로 보이지만 원본 생성 코드는 저장소에 없어 단정할 수 없다. 파생 데이터에서는 다음 두 값을 분리해야 한다.

- `source_total_chars`: 원본 메타데이터 값
- `indexed_text_chars`: 실제 정제 후 문자열 길이

## 12. 파일럿 품질 게이트

파일럿 색인 전에 각 문서를 다음 상태 중 하나로 분류할 것을 권장한다.

| 상태 | 조건 | 처리 |
|---|---|---|
| `ready` | PDF 연결 1:1, 파싱 성공, 충분한 텍스트, 제어문자 비율 허용 | 색인 |
| `warning` | 날짜/저자/제목 신뢰도가 낮지만 본문 사용 가능 | 경고와 함께 색인 |
| `duplicate` | 동일 PDF에 여러 JSON 레코드 | 대표 레코드만 색인, 전체 계보 보존 |
| `orphan_pdf` | PDF는 있으나 JSON 없음 | 자동 색인 보류, 재추출 대기 |
| `low_text` | `full_text <= 1,000` 또는 빈 페이지 비율 과다 | OCR/재추출 대기 |
| `corrupt_text` | 제어문자/비인쇄 문자 비율 임계값 초과 | 색인 금지, 대체 추출 |
| `manual_review` | 제목 잘림, 날짜 충돌, 연결 충돌 | 인간 검토 |

최소 완료 기준:

- 색인된 모든 문서는 하나의 실제 PDF와 연결된다.
- 모든 검색 결과는 `document_id`, PDF 상대 경로, 페이지 번호를 가진다.
- `low_text`와 `corrupt_text`는 기본 검색 결과에서 제외된다.
- 중복 레코드는 한 번만 점수에 기여한다.
- `data/`의 파일 해시는 처리 전후 동일하다.

## 13. 우선 처리 순서

1. 고유 매니페스트와 orphan/duplicate 보고서를 생성한다.
2. 색인 전 품질 게이트를 적용한다.
3. NFC 정규화 키와 저장소 상대 경로를 만든다.
4. 유형별 제목·저자·발행일·초록/요약 파서를 구현한다.
5. 저추출 38개와 손상 연구보고서 1개를 별도 재추출/OCR 티켓으로 처리한다.
6. 파일명 길이 위험 문서의 제목을 표지에서 복원하고 인간 검토한다.

이 순서를 구현 티켓으로 구체화한 내용은 [IMPLEMENTATION_PLAN.md](./IMPLEMENTATION_PLAN.md)에 있다.
